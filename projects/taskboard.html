CASE STUDY · REACT + TYPESCRIPT

TaskBoard

Task dashboard demo built with React 18, TypeScript and Vite: search, filter, sort, live stats and localStorage persistence.

RoleSole developer
StackReact 18, TypeScript, Vite, Vitest
StatusLive demo

Goal

Prove production-style React and TypeScript skills beyond HTML/CSS/JS: typed components, derived state, tested business logic and honest loading, error and empty states.

What was built

  • Task dashboard with search, status filter and three sort modes
  • Live stats cards derived from task state
  • Add, complete, delete and overdue highlighting, persisted to localStorage
  • Loading skeletons, an error state with retry, and an empty state

Key decisions

  • Vite over Next.js: the app is fully client-side, so a static build deploys anywhere with zero config
  • Business logic as pure functions in a framework-free module, so filtering, sorting and stats are unit-tested with Vitest
  • No component library: hand-written CSS shows fundamentals and keeps the bundle small

Challenge

Keeping UI state, derived stats and persistence consistent without a state library. Solved by keeping one source of truth in App.tsx, deriving everything with useMemo, and funneling every mutation through a single update function that also persists.

Testing

21 Vitest unit tests cover filtering, sorting, stats, mutations, tags, calendar grid and due-date labels. npm run build runs the TypeScript compiler before bundling, so type errors fail the build.

Note

Built with AI assistance under my direction; I chose the product, stack and features, reviewed the code, and own the tests. See the README for the AI-assisted development notes.
